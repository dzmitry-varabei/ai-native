# Контекст агента

> База · до этого: [LLM, harness и агент](llm-agent-harness.md) · [Карта](../README.md)

**Главное.** Контекст — всё, что модель видит в момент ответа. Одна и та же модель выдаст хороший результат или мусор в зависимости от того, что лежит в контексте. Поэтому им управляют: дают нужное, убирают лишнее, а постоянные знания о проекте записывают в файлы.

## Из чего складывается контекст

- **Стартовая часть** — загружается до вашего первого сообщения: системный промпт, инструменты, файлы с правилами проекта, память, краткие описания skills.
- **Ваша задача** — формулировка, ссылки, примеры.
- **То, что агент прочитал** — файлы, результаты поиска, вывод тестов. Всё это остаётся в истории, пока контекст не сжат (compaction) или не очищен.

Лишнее вредит так же, как недостающее: шум отвлекает модель и стоит денег. Хороший вопрос перед задачей: что агенту нужно прочитать, а что — нет?

## Что Claude Code читает при старте

- **CLAUDE.md проекта** — правила, которые команда хранит в репозитории. Загружаются файлы из рабочей папки и всех папок выше неё. CLAUDE.md во вложенных папках подтягивается позже, когда агент открывает там файлы.
- **Личные файлы** — `~/.claude/CLAUDE.md` (ваши правила для всех проектов) и `CLAUDE.local.md` (ваши правила для этого проекта, не коммитятся).
- **AGENTS.md** — открытый стандарт того же назначения, его понимают разные агенты. Надёжный способ подключить его в Claude Code — CLAUDE.md со строкой `@AGENTS.md`: так файл читается при любых настройках. Свежие версии Claude Code умеют читать AGENTS.md и сами, но только пока рядом нет CLAUDE.md или CLAUDE.local.md.
- **Автопамять** — заметки, которые агент сам ведёт по вашим поправкам. Они машинно-локальные и в репозиторий не попадают.

Проверить, что реально загрузилось, можно командой `/context` (команды и поведение — на сентябрь 2026, Claude Code быстро меняется). Файлы читаются один раз при старте: правка CLAUDE.md посреди сессии заработает после `/clear`, `/compact` или перезапуска.

Модель может правило пропустить, особенно если файл длинный или правила противоречат друг другу. Если нарушение недопустимо, правило выносят в [хук](hooks.md). ## Каким должен быть CLAUDE.md

- **Короткий.** Файл уходит в каждый запрос. Документация советует держать его в пределах 200 строк: чем длиннее, тем хуже модель следует правилам.
- **Только то, чего нет в коде.** Как запустить и протестировать проект, конвенции, архитектура в нескольких строках, известные ловушки. Пересказывать код не нужно: агент прочитает его сам.
- **Живой.** Проект меняется — файл тоже. Устаревшее правило хуже отсутствующего: агент уверенно сделает по-старому. Заметили, что агент дважды ошибся в одном месте, — допишите строку.
- **Без противоречий.** Два конфликтующих правила — и модель выберет одно наугад.

Черновик файла агент может написать сам, просканировав репозиторий (в Claude Code — команда `/init`). Дальше его правит и поддерживает команда.

## Секреты

Всё, что агент прочитал, ушло к провайдеру модели и осталось в истории сессии. Поэтому:

- **Не хардкодьте токены** в `.mcp.json`, `.env` и других файлах, которые агент может открыть. В конфиге — ссылка на переменную окружения, сама переменная задаётся вне репозитория. Учтите: процесс агента эту переменную видит (например, через shell).
- **Закройте доступ программно**: запретите чтение `.env` в настройках разрешений (правило `deny`), для страховки — ещё и [хуком](hooks.md). Просьба «не читай .env» в CLAUDE.md не защищает.
- **Секрет засветился** в сессии — считайте его скомпрометированным и перевыпустите.

Подробно — лонгрид [«Из чего сделан агент»](../longread/02-fundamentals.md), понятие 4.

## Проверь себя

- Вы пришли на проект, где нет ни CLAUDE.md, ни AGENTS.md. Что вы запишете в первую версию файла, а что специально оставите за бортом?
- В CLAUDE.md написано «используй pnpm», а агент упорно запускает npm. Какие три причины вы проверите?
- В репозитории есть AGENTS.md, вы добавили себе CLAUDE.local.md, и агент перестал следовать правилам команды. Что проверите?
- CLAUDE.md разросся до тысячи строк, и агент стал путаться. Что будете делать?
- Для MCP-сервера нужен токен доступа к трекеру. Куда вы его положите и почему не в конфиг в репозитории?
