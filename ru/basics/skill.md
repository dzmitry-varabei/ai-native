# Skill: переиспользуемый шаг работы

> База · до этого: [контекст](context.md) · [Карта](../README.md)

**Главное.** Skill — записанная в файл инструкция «как у нас делают X», которую агент подгружает, когда она нужна. Вместо того чтобы в каждой сессии заново объяснять одно и то же, вы один раз записываете способ работы, проверяете его и дальше переиспользуете.

## Чем skill отличается от промпта

- **Промпт** живёт в одном разговоре. Закрыли сессию — он пропал, в следующий раз пишете заново и немного по-другому.
- **Skill** лежит в файлах репозитория: его коммитят, ревьюят, версионируют и передают другому человеку или агенту.

Образ из лонгрида: skill — **корпоративная методичка**, проверенная на десятках задач. Новый сотрудник не изобретает процесс, а открывает методичку.

## Как это устроено в Claude Code

- **Папка со `SKILL.md`.** Проектные skills лежат в `.claude/skills/<имя>/SKILL.md`, личные — в `~/.claude/skills/`. Рядом могут лежать шаблоны, справочники и скрипты.
- **Описание (`description`)** в начале файла. Описания skills загружаются в контекст при старте, чтобы агент знал, что у него есть. По описанию он решает, когда skill применить.
- **Полный текст** загружается только при вызове: агент решил, что skill подходит, или вы вызвали его сами командой `/имя`.
- **Открытый стандарт.** Формат совпадает с открытым стандартом Agent Skills, так что skill не привязан к одному инструменту.

Для действий с последствиями (деплой, отправка сообщений) автовызов можно выключить — тогда skill запускает только человек.

## Какого размера должен быть skill

Конвенция из лонгрида: **один skill — один шаг, который можно проверить отдельно.**

- **Хороший размер:** «извлечь из тикета критерии приёмки», «собрать дифф и список затронутых модулей», «проверить PR на секреты».
- **Слишком крупно:** «провести код-ревью». Это цепочка шагов: собрать дифф → проверить безопасность → проверить конвенции → сформулировать замечания.

Маленький шаг можно протестировать как функцию: подать известный вход несколько раз и сравнить результат с эталоном или списком критериев.

Агент в этой логике — координатор: запускает нужные skills в нужном порядке и держит контекст между ними. Тревожный признак — агентов в проекте становится больше, а библиотека skills не растёт. ## Когда писать skill

- **Вы объясняете агенту одно и то же в третий раз.** Пора записать.
- **Шаг повторяется у всей команды.** Один проверенный skill лучше десяти личных промптов.
- **Шаг можно сделать скриптом** — сделайте скриптом. Он повторяем и не тратит токены. Skill может просто вызывать этот скрипт.

Каждый новый skill — часть второго выхода [фабрики](factory.md): следующая похожая задача обходится дешевле.

## Проверь себя

- Вы третий раз объясняете агенту, как у вас в проекте называются ветки и оформляются коммиты. Что сделаете?
- Коллега написал skill «сделай фичу от тикета до PR» на 400 строк. Что с ним не так и как бы вы его разбили?
- Skill для извлечения критериев приёмки на одном тикете отработал отлично. Достаточно ли этого, чтобы отдать его команде?
- Skill каждый раз просит модель пересчитать статистику по логам. Что здесь можно улучшить?
