# LLM, harness и агент

> База · обязательно до старта · дальше: [контекст](context.md) · [Карта](../README.md)

**Главное.** LLM — модель, которая только продолжает текст. Harness (обвязка) — программа вокруг неё, которая даёт инструменты, запускает цикл работы и решает, какой текст отправить модели. Агент — LLM в harness, настроенная на конкретную роль: она сама выбирает следующий шаг в своей работе. В модель уходит не весь ваш репозиторий, а только то, что harness положил в запрос.

## Три понятия

- **LLM (большая языковая модель).** Получает текст и продолжает его. Может написать «вызови инструмент X с такими аргументами», но сама ничего не вызывает. Между вызовами ничего не помнит: каждый запрос начинается с чистого листа.
- **Harness.** Claude Code, Cursor, Copilot в agent-режиме. Крутит цикл: отправил запрос → модель попросила инструмент → harness его выполнил (прочитал файл, запустил тесты) → вернул результат модели → повторил. Хранит историю и решает, когда остановиться.
- **Агент.** LLM + harness + роль (какую работу делает, какие правила соблюдает). Один и тот же механизм становится ревьюером или генератором тестов в зависимости от роли.

Образ из лонгрида: LLM — **консультант на телефоне**. Знает много и продиктует, что делать, но сам ни одной кнопки не нажмёт, а положив трубку, забудет разговор. Harness — **рабочее место**: ноутбук, доступы, терминал.

## Что уходит в запрос к API

Раз модель ничего не помнит, harness на каждом шаге заново отправляет ей всё, что она должна «знать». Ваше сообщение — лишь малая часть запроса. Обычно в нём есть:

- **системный промпт** — инструкции harness о том, как себя вести и как пользоваться инструментами;
- **описания инструментов** — какие есть инструменты и с какими аргументами их вызывать (для MCP-серверов — как минимум их список; MCP — способ подключить к агенту внешние инструменты: трекер задач, базу, документацию);
- **сведения об окружении** — рабочая папка, ОС, ветка git, последние коммиты;
- **файлы памяти** — CLAUDE.md (правила проекта) и ваша личная память;
- **список skills** — краткие описания доступных [skills](skill.md);
- **история сессии** — ваши сообщения, ответы модели и результаты инструментов;
- **ваше сообщение.**

Файлы проекта попадают в запрос, **только когда агент их прочитал** инструментом: открыл файл, выполнил поиск, запустил команду. С этого момента содержимое — часть истории и уходит в каждом следующем запросе, пока контекст не сжат (compaction) или не очищен.

## Чего в запросе нет

- **Всей кодовой базы.** Claude Code не загружает репозиторий целиком: агент ищет и читает файлы по одному, как человек в редакторе.
- **Прошлых сессий.** Новая сессия начинается с пустой истории. Переносится только то, что записано в файлы: CLAUDE.md, память, спеки.
- **Того, что вы «имели в виду».** Модель видит только текст запроса. Не записали — агент не знает.

Отсюда практический вывод: всё, что агент прочитал, ушло к провайдеру модели. Поэтому секреты не должны лежать там, где агент их прочитает, — подробнее в [контексте](context.md#секреты).

<summary>Подробнее: как это увидеть своими глазами</summary>

- В Claude Code команда `/context` показывает, из чего сейчас состоит контекст: системный промпт, инструменты, файлы памяти, история.
- Документация Claude Code разбирает, что загружается при старте и что добавляется по ходу сессии: [Explore the context window](https://code.claude.com/docs/en/context-window).
- Чтобы увидеть сам обмен с API, запросы можно пустить через свой прокси или LLM-шлюз и посмотреть их тело. Учтите: через свой адрес часть оптимизаций выключается (например, отложенная загрузка MCP-инструментов), и запрос будет толще обычного. Это хорошее упражнение: один раз увидев, сколько текста уходит на короткую реплику, вы иначе посмотрите и на контекст, и на [токены](tokens.md).

## Проверь себя

- Коллега говорит: «Не буду пускать Claude Code в репозиторий заказчика, он отправит в облако весь код». Что вы ему ответите и с какой оговоркой?
- Вчера вы долго объясняли агенту архитектуру модуля. Сегодня открыли новую сессию, и он «ничего не помнит». Почему и что сделать, чтобы это не повторялось?
- Агент прочитал большой лог на тысячи строк в начале сессии. Как это скажется на следующих шагах этой сессии?
- Где в этой цепочке модель, а где harness: «агент запустил тесты и увидел, что два упали»?
