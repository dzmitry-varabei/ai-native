# Стек Java: к интервью

> Стек: [JS/TS](stack-js.md) · [.NET](stack-dotnet.md) · Java · [Как проходит интервью](how-it-goes.md) · [Карта](../README.md)

**Главное.** Берут на Java — собеседуют по Java: Java Core, Spring, брокеры сообщений, базы. AI и облако спрашивают немного и в конце.

## Что спрашивали

- **Java Core** — в целом базовые вещи.
- **Spring Framework** — что это такое.
- **Kafka и RabbitMQ** (брокеры сообщений: сервисы обмениваются через них сообщениями, а не прямыми вызовами).
- **Немного AI и AWS** — дополнительными вопросами после основной части. AI-вопросы — [отдельно](ai-part.md).
- **Многопоточность** — собирались спросить, но не стали. Готовьтесь.

## MUST HAVE

- **Java Core:** коллекции, исключения, ООП, основы многопоточности (потоки, синхронизация, почему общее состояние опасно).
- **Spring Boot:** DI (зависимости передаются в класс извне, а не создаются внутри), слои контроллер → сервис → репозиторий, работа с базой через ORM.
- **Базы:** SQL или NoSQL. Для SQL — JOIN и агрегация без подсказок; для любой базы — индексы, транзакции, N+1 (список из N записей тянет N лишних запросов).
- **Микросервисы:** зачем их делят, как они общаются — через HTTP или через брокер сообщений.
- **Docker и Kubernetes — основы:** что такое контейнер, поднять сервис с базой через docker-compose, зачем нужен оркестратор.
- **Тесты:** unit и integration, тестовая пирамида. На части проектов нет тестировщиков — всё держится на автотестах.
- **Фронт на уровне чтения:** на части Java-позиций нужно читать код на React и Node.js.

## NICE TO HAVE

- **AWS:** что решает облако, чем управляемый сервис отличается от своего сервера.
- **Kafka и RabbitMQ глубже:** в чём разница, когда какой.
- **Node.js:** понимание, как устроен сервер на JS.
- **Git worktree:** две задачи — две рабочие копии — две сессии агента параллельно.

<details>
<summary>Как тренировать чтение чужого Spring-проекта</summary>

Возьмите небольшой открытый проект на Spring Boot. За 30–40 минут найдите точку входа, контроллеры, сервисы, работу с базой, главные сущности и несколько подозрительных мест. Это рабочая ситуация: код пишет агент, а вы его проверяете.

</details>

## Проверь себя

- Могу ли я объяснить, что делает Spring, когда я пишу `@Autowired` или внедряю зависимость через конструктор?
- Два потока меняют один счётчик, итог «плавает». Могу ли я объяснить почему и как это починить?
- Сервис A должен сообщить сервису B о новом заказе. Когда я выберу HTTP-вызов, а когда — брокер сообщений?
- Могу ли я поднять свой сервис с базой одной командой в Docker и объяснить, что где крутится?
- Агент сделал эндпоинт и тесты к нему. Как я проверю, что тесты ловят реальный сценарий, а не просто дают покрытие?
