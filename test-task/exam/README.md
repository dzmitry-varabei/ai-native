# Тестовое к интервью

> [Тестовое и курс](../README.ru.md) · [Правила сдачи](../rules.ru.md)

Три задания на коде [BrownEvents](https://github.com/dzmitry-varabei/brown-events-pilot) — браунфилд на ASP.NET Core 6 + EF Core 6 + React + Vite + PostgreSQL. Они проверяют базу, без которой работа с агентом превращается в чат: настроенное рабочее место, понимание проекта и умение довести фикс до доказанного результата.

**Срок.** Около двух дней, если вы уверенно владеете стеком. Если нет — дольше, это нормально: важнее, чтобы вы могли проверить работу агента, а не применить её вслепую.

## Порядок

Строго по порядку, каждое опирается на предыдущее:

1. [T1 — Рабочее место](T1-workplace.md): GitHub MCP, закрытые секреты, что уходит в модель.
2. [T2 — Карта и CLAUDE.md](T2-map-and-context.md): карта проекта и короткий файл знаний для агента.
3. [T3 — Один баг тремя способами](T3-one-bug-three-ways.md): воспроизвести, закрепить тестом, сравнить три способа.

Как сдавать — ветки, PR, devlog, отчёт аналитики — в [правилах](../rules.ru.md). Как проходит сам созвон — [здесь](../../ru/interview/how-it-goes.md).

## Что должно быть готово к созвону

- Issues T1–T3 в вашем репозитории, созданные агентом через MCP
- `.claude/settings.json` (или аналог) с запретом на `.env` и конфиг MCP; вывод заблокированной попытки чтения
- `docs/architecture.md` — карта бэка и фронта с ER-диаграммой и потоками запросов
- `CLAUDE.md` (или `AGENTS.md`) до 50 строк
- Три ветки T3, одна из них смержена через PR; в каждой — тест, падающий без фикса
- `docs/devlog.md`: ответы на «Объясни» по каждому заданию, до/после для `CLAUDE.md`, таблица способов T3, стоимость каждой задачи
- Готовность рассказать регистрацию от фронта до базы с тестами, не открывая файлы

## Что не входит

CI, большая фича по спеке, миграция бэкенда, e2e-набор — это [курс](../course.ru.md). Тестовое проверяет базу, курс её развивает.
