# Правила сдачи

> [Тестовое задание](README.ru.md) · [Карта репозитория](../ru/README.md)

**Главное.** Каждое задание — это цепочка «issue → ветка → сессии агента → коммиты → PR» с записью в devlog. По этой цепочке проверяющий видит не только результат, но и то, как вы к нему пришли.

## Трассировка

1. **Одно задание — одна ветка** с номером задания: `git checkout -b BEVN-001-codebase-map`. С агентом работайте только из этой ветки. Исключение — [T3](exam/T3-one-bug-three-ways.md): три ветки от одного коммита (`T3-a-…`, `T3-b-…`, `T3-c-…`), через PR мержится одна.
2. **Первое сообщение каждой сессии агента начинается с номера:** «*BEVN-115: воспроизведи баг с модалкой…*». В отчёте это название сессии.
3. **Коммиты — с номером:** `docs: add architecture map (BEVN-001)`.
4. **Одно задание — один PR** из ветки в `main` вашей копии. Номер в заголовке, в описании ссылка на issue (`Closes #N`). Проверили DoD — мержите сами.

Количество сессий, попыток и уточнений не штрафуется. Смотрят на подход: как вы ставите задачу, как итерируете, доводите ли до результата.

## Что агент делает сам, а что — только вы

- **Сам:** читает код, запускает тесты, создаёт ветки.
- **Через ваш PR:** любые изменения кода и документов.
- **Только вы:** мерж, удаление чего-либо, секреты.
- **Только по вашей явной команде:** всё, что уходит наружу (issues, комментарии, письма). Так агент создаёт issues через MCP в EXT-100 и T1: вы ставите задачу и проверяете результат.

Правило простое: чем труднее откатить действие, тем меньше у агента самостоятельности. Подробнее — [фабрика](../ru/basics/factory.md).

## Devlog

Ведите `docs/devlog.md`: после каждого задания раздел с его номером. Пишет агент или вы, но в записи должно быть ваше, а не пересказ диффа:

- что делали и что получилось;
- какие решения агент принял **сам** и почему вы их приняли или переделали;
- где пришлось вмешаться руками;
- **ответы на «Объясни»** из задания;
- **цена задачи** одной строкой;
- **что здесь могло быть скриптом**, а не работой агента.

В шаблоне PR вашего репозитория есть чекбокс «devlog обновлён». Без записи задание не закрыто. Хороший devlog — готовый конспект для созвона: через две недели без него вы не вспомните и половины.

**Уходите на паузу — оставьте записку.** Перед перерывом попросите агента записать в файл, где вы остановились и что дальше. Новая сессия с этим файлом дешевле, чем старая после долгой паузы. Почему — в [токенах](../ru/basics/tokens.md).

## Свободно или через спеку

- **Свободно** — работаете с агентом как удобно.
- **Через спеку** (spec-driven, помечено в задании) — до первой строки кода в ветке появляются спека (что строим, спорные случаи решены) и план (как, по шагам). Оба файла коммитятся вместе с кодом, проверяющий читает их до диффа. В Claude Code для этого ставится плагин [superpowers](https://github.com/obra/superpowers). В другом агенте повторите тот же поток: файлы `spec.md` и `plan.md` в PR обязательны. Подробнее — [спека](../ru/basics/spec.md).

**CI как гейт.** Если в вашей копии есть CI, PR мержится только с зелёным пайплайном. Красный пайплайн — часть задачи, а не фон.

## Отчёт о работе с агентом

Запустите отчёт после первого же задания — сразу увидите, сколько оно стоило. В конце соберите финальный. Из папки репозитория:

```bash
npx -y -p @codemieai/code codemie analytics --report \
  --last 30d --include-external \
  --project brown-events-pilot \
  --report-format both --report-output ./report/report.html
```

`--project` — это имя папки с репозиторием. Если назвали иначе, подставьте своё. Если работали дольше 30 дней, вместо `--last 30d` укажите даты: `--from … --to …`. Откройте `report/report.html` и проверьте глазами: внутри только сессии этого проекта. Что попадает в отчёт — в [инструкции](codemie-analytics.md). Оба файла закоммитьте последним PR и напишите проверяющему.

## Что оценивается

- **Результат:** выполнен ли DoD, работает ли то, что сделано, и есть ли этому доказательство в PR.
- **Понимание:** ответы на «Объясни» и рассказ на созвоне — по вашим же артефактам.
- **Работа с агентом:** как ставите задачи и замечаете ли решения, которые агент принял молча.
- **Трассировка и цена:** читается ли цепочка «задание → сессии → коммиты → PR», знаете ли вы, сколько стоила работа.
