# Тестовое задание: BrownEvents

> [Карта репозитория](../ru/README.md) · [Правила сдачи](rules.ru.md) · English version — soon

**Главное.** Три задания на браунфилд-приложении BrownEvents. Они проверяют базу, без которой работа с агентом превращается в чат: настроенное рабочее место, понимание проекта и умение довести фикс до доказанного результата. После них — созвон.

**Срок.** Около двух дней, если вы уверенно владеете стеком. Если нет — дольше, и это нормально: важнее, чтобы вы могли проверить работу агента, а не применить её вслепую. Дедлайна нет.

## С чем вы работаете

BrownEvents — приложение для конференций, которое два года никто не поддерживал. Стек: **ASP.NET Core 6 + EF Core 6 + React + Vite + PostgreSQL**, запуск через `docker-compose`.

Код лежит в репозитории-шаблоне **[brown-events-pilot](https://github.com/dzmitry-varabei/brown-events-pilot)**. Нажмите **Use this template** и создайте свою копию. Если копия приватная, добавьте проверяющего коллаборатором. Вся работа идёт в ней: issues, ветки, PR, devlog, отчёт.

Нужны **консольный AI-агент** (Claude Code, Codex CLI, Gemini CLI, Copilot CLI или Pi; Cursor, веб-чаты и плагины IDE не подходят — их сессии не попадут в отчёт), **Docker** и **Node.js 20+**.

## Задания — строго по порядку

1. [T1 — Рабочее место](exam/T1-workplace.md): GitHub MCP, закрытые секреты, что уходит в модель.
2. [T2 — Карта и CLAUDE.md](exam/T2-map-and-context.md): карта проекта и короткий файл знаний для агента.
3. [T3 — Один баг тремя способами](exam/T3-one-bug-three-ways.md): воспроизвести, закрепить тестом, сравнить три способа.

Каждое задание устроено одинаково: **Зачем** → **Тикет** (по-английски, как на проекте) → **Definition of Done** → **Докажи, что работает** (что приложить к PR) → **Объясни** (ответ своими словами в devlog; на созвоне спросят о том же) → **Цена**.

Как сдавать — ветки, PR, devlog, отчёт аналитики — в [правилах](rules.ru.md). Прочитайте их до первого задания.

## Что должно быть готово к созвону

- Issues T1–T3 в вашем репозитории, созданные агентом через MCP
- Запрет агенту на чтение `.env` и конфига MCP; вывод заблокированной попытки
- `docs/architecture.md` — карта бэка и фронта с ER-диаграммой и потоками запросов
- `CLAUDE.md` (или `AGENTS.md`) до 50 строк
- Три ветки T3, одна из них смержена через PR; в каждой — тест, падающий без фикса
- `docs/devlog.md`: ответы на «Объясни», до/после для `CLAUDE.md`, таблица способов T3, стоимость каждого задания
- Готовность рассказать регистрацию от фронта до базы с тестами, не открывая файлы

Как проходит сам созвон — [здесь](../ru/interview/how-it-goes.md).
